    Interface TestOptions

    Options that control how measures run. Set them in the config file, or pass them to describe, test and measure. Nested blocks inherit options from enclosing blocks and can override them.

    A measure first warms up the callback. Then it runs batches of calls with a pause after each batch. A batch calls the callback in loops, and times each loop as a whole. The mean duration of a call in a batch is one sample, and the measure stops when samples agree within targetRme, or when measureTimeout is reached.

    interface TestOptions {
        batchPauseDuration?: number;
        batchTimeout?: number;
        maxBatchIterationCount?: number;
        maxBatchMemorySampleCount?: number;
        maxWarmupBatchIterationCount?: number;
        measureTimeout?: number;
        minBatchCount?: number;
        minLoopDuration?: number;
        targetRme?: number;
    }

    Properties

    OptionalbatchPauseDuration

    batchPauseDuration?: number

    The pause after each batch in milliseconds. It gives the garbage collector time to run between batches instead of during them.

    Default

    200

    OptionalbatchTimeout

    batchTimeout?: number

    The maximum duration of a batch in milliseconds. A batch always times at least one loop, even if that loop takes longer.

    Default

    1_000

    OptionalmaxBatchIterationCount

    maxBatchIterationCount?: number

    The maximum number of calls in a batch, including untimed calls that measure memory and calibrate loops. Set it if beforeBatch prepares data for a limited number of calls.

    Default

    Infinity

    OptionalmaxBatchMemorySampleCount

    maxBatchMemorySampleCount?: number

    The maximum number of memory samples in a batch. A memory sample is an extra call after a loop, which measures how many bytes the callback allocates instead of how long it takes. Set to 0 to skip measuring memory.

    Default

    10

    OptionalmaxWarmupBatchIterationCount

    maxWarmupBatchIterationCount?: number

    The maximum number of calls during warmup. V8 optimizes a function after it has been called many times, so warmup keeps slow unoptimized calls out of the results. Warmup is also limited by batchTimeout and maxBatchIterationCount. Set to 0 to skip warmup.

    Default

    10_000

    OptionalmeasureTimeout

    measureTimeout?: number

    The maximum duration of a measure in milliseconds, not counting warmup. When it's reached, the measure stops even if targetRme isn't reached yet.

    Default

    10_000

    OptionalminBatchCount

    minBatchCount?: number

    The minimum number of batches before targetRme can stop the measure. A few batches may agree by chance, for example, while the CPU is changing its frequency. measureTimeout still stops the measure if it's reached first.

    Default

    5

    OptionalminLoopDuration

    minLoopDuration?: number

    The minimum duration of a timed loop in milliseconds. A fast callback is called many times in a loop that is timed as a whole, so the overhead and resolution of the timer don't distort results.

    Loops are shorter if maxBatchIterationCount is too small, and have a single call if there are beforeIteration or afterIteration hooks.

    Default

    1

    OptionaltargetRme

    targetRme?: number

    The relative margin of error at which the measure stops, between 0 and 1. For example, 0.05 stops the measure when the mean call duration is known within ±5% at 95% confidence.

    Default

    0.05
